## 一、账号：用老号，别开新号

**结论：找回你原来的账号继续用。不要申请新号，更不要买"老号"。**

| 疑问 | 真实情况 |
|---|---|
| 新号会不会没流量？ | GitHub **没有**短视频那种算法推流。分发靠搜索、Topics、Trending 和外部链接。账号年龄不是搜索排序的主导因素，**活跃度和仓库质量权重高得多** |
| 老号不常用，会不会有污点？ | 不常用不是问题。只要没违规封禁，历史 commit 反而是信任信号 |
| 能开第二个免费号吗？ | **不能**。GitHub 服务条款明确「一个人最多一个免费个人账户」。有真实案例：多注册免费号被风控检测，两个号一起封，申诉一个月才解封 |
| 那买个现成老号？ | 灰色产业，违反 ToS 第 4.2 条（禁止账号买卖转让），且可能是黑产号、钓鱼号。别碰 |

**找回步骤**（GitHub 官方文档）：
1. 访问 `github.com/password_reset`，输入主邮箱或已验证的备用邮箱，重置密码（重置链接 3 小时内有效）
2. 如果开了两步验证且丢失凭据 → 走 `Account recovery` 流程
3. 找回后立刻检查：绑定邮箱是你自己的、开启 2FA、把邮箱加到 git commit 的 `user.email`

**一个提醒**：commit 作者邮箱最好和 GitHub 账号主邮箱一致，否则贡献图不记你的号。
本机 git 邮箱见 [上传手册](UPLOAD_GUIDE.md) 的占位符提示（已脱敏），如果和 GitHub 主邮箱不同，在 GitHub Settings → Emails 把这个邮箱加为备用并验证即可。

> 📌 **三个平台的具体改造步骤**（昵称怎么定、GitHub 改名副作用、B站/小红书规则坑、
> 统一头像、11/24–11/29 执行顺序）见 **[BRAND_SETUP.md](BRAND_SETUP.md)**。
> 关键结论：三个号都不换，一次性统一改造；**先改 GitHub 用户名，再上传项目分享链接**——
> 因为改名后个人主页旧链接会 404（只有仓库链接重定向）。

## 二、主页观感：首屏 30 秒决定一切

访客停留 30–60 秒就是整个漏斗。按下面顺序改，收益从大到小：

### 1. 仓库设置（网页端，5 分钟，别漏）

```bash
# 如果有 gh CLI 可以命令行设置；没有就手动在仓库页 About 区域填
gh repo edit jax-fox-lab/ai-selfstudy-30weeks \
  --description "软件工程背景自学 AI 的 30 周开源路线图：每周作业 + 打卡看板 + 真实产出" \
  --homepage "https://OWNER.github.io/REPO/" \
  --add-topic "machine-learning" --add-topic "ai" --add-topic "self-study" \
  --add-topic "roadmap" --add-topic "deep-learning" --add-topic "chinese"
```

- **About 描述**：显示在任何分享卡片和搜索结果里，放搜索词，不要写「我写的一个小项目」
- **Topics**：让仓库进入 `github.com/topics/roadmap` 这类聚合页，是被发现的主要入口
- **Social preview**：Settings → Social preview → 上传 `docs/social-preview.png`（已生成好，1280×640）。
  不传的话，分享到微信/Slack/X 时 GitHub 会拿你的头像凑数
- **Website**：开 Pages 后填在线地址（Settings → Pages → Source 选 `/docs`）

### 2. README 首屏（已优化好）

现在的结构遵循 Answer-First：

```
H1（一句话说清是什么、给谁）
  ↓
价值主张 + 项目预览图
  ↓
徽章（5 个，每个回答一个问题：能不能构建/是否活跃/许可证/语言/是否接受贡献）
  ↓
「为什么不一样」表格 —— 给读者一个 star 的理由
  ↓
Quick Start（30 秒能跑起来）
  ↓
自动统计区块（进度 + 热力图 + 产出数）
```

**千万别做**：首屏堆 15 个花哨徽章、贪吃蛇动画、rap lyrics 生成器。
这些只会让人觉得「这人有时间搞装修」。你项目的说服力是**真实的 30 周记录和产出**。

### 3. 个人主页（同名仓库）

建一个和用户名同名的公开仓库（如 `lzxing/lzxing`），里面的 README.md 会显示在你的 GitHub 主页顶部。
内容保持简短：一句话介绍 + 3 个精选项目链接（这个计划排第一）+ 联系方式。
Profile README 负责建立信任，Pinned 仓库负责提供证据，两者协同。

## 三、自媒体：定位与平台

### 定位（一句话）

> **「一个软件工程师用 30 周从零自学 AI 的全过程公开记录」**

这个定位的优势：
- **真实感**：不是大佬教学，是同路人记录。观众爱看「正在发生」的过程，尤其是踩坑
- **有终点**：30 周有明确截止日期，天然构成连载，比「不定期分享」更容易追更
- **有可视化证据**：GitHub 贡献图、自动统计、热力图——进度不是嘴说的，是数据
- **有差异化**：双机（Mac + Windows）、软件工程背景转 AI、开源项目形式——三个记忆点

### 平台选择（不要一开始铺四个）

| 平台 | 定位 | 发什么 | 优先级 |
|---|---|---|---|
| **B站** | 主阵地，长内容沉淀 | 每周 8–12 分钟复盘视频：这周学了啥、代码演示、踩坑 | ⭐ 优先 |
| **小红书** | 引流入口，图文快 | 周打卡卡片（用 progress.svg 截图）+ 知识点一图流 + 资源清单 | ⭐ 优先 |
| **掘金 / 公众号** | 技术深度，SEO | 阶段性长文：数学基础梳理、LoRA 实战复盘、双机同步方案 | 第二阶段 |
| 抖音/视频号 | 谨慎 | 短视频需要另做剪辑，成本高，前期不建议 | 暂缓 |

**为什么 B站 + 小红书**：B站适合 10 分钟讲清一个主题的「周复盘」，用户停留时间长、
评论区能沉淀技术讨论；小红书适合把打卡数据做成图文卡片，传播门槛低、容易带来初始关注。
两个平台的内容**同素材不同剪法**，不要重复劳动。

### 内容支柱（四大类，轮流发）

1. **周复盘**（主线，每周 1 条）——「W13：我用 CNN 把 CIFAR-10 跑到了 82%」
   结构：本周目标 → 代码演示 → 实验结果 → 踩的坑 → 下周计划。直接对应 `weeks/wNN/README.md`
2. **踩坑实录**（最容易爆）——「Mac 上 LoRA 训练 loss 变 NaN，我排查了 3 小时」
   直接来自 `LEARNINGS.md`。这类内容真诚、具体、可搜索，是技术自媒体的硬通货
3. **工具/方法论**（展示项目价值）——「我用 GitHub 做了一个会自动更新的学习看板」
   讲 Actions 自动统计、双机进度合并、产出索引。这类内容给项目引流
4. **阶段里程碑**（节点引爆）——阶段一完成、W20 第一次微调成功、Capstone 演示
   做成更有仪式感的长视频或长文，适合集中投放

## 五、单条内容的生产流水线（关键：别让自媒体拖垮学习）

核心原则：**内容从学习产出中"长出来"，不是额外重做一遍。**

```
周一~周五  正常学习，在 weeks/wNN/README.md 随手记「踩的坑」和关键结论
     ↓
周五      打开周记，勾出 3 个能讲的點（1 个成果 + 1 个坑 + 1 个结论）
     ↓
周六      按固定模板录 B站视频（不用精致剪辑，录屏 + 讲解即可，8–12 分钟）
     ↓
周六      从视频里截 3–5 张图 → 拼成小红书图文卡片（15 分钟）
     ↓
周日      push 本周产出 + 进度 JSON → Actions 自动更新 README
     ↓
周日      发视频 + 图文，简介/正文统一挂 GitHub 仓库链接
```

**每次发布都要挂仓库链接**——自媒体是引流入口，GitHub 才是资产沉淀地。
观众关注你是因为内容，但真正产生长期价值的是那个持续更新的仓库和贡献图。

**时间段建议**：B站晚 19:00–22:00，小红书午休 12:00–13:00 或晚 20:00–22:00。

## 六、增长指标与常见误区

### 该看的指标（按优先级）

1. **GitHub star 增速**——最真实的价值信号，来自内容的 star 转化率高
2. **视频完播率**——B站后台看，>40% 说明内容节奏对
3. **小红书收藏量**——>点赞量说明内容是「有用」而非「好看」
4. **评论里的具体问题**——是最好的下期选题来源

### 别踩的坑

| 误区 | 为什么要避开 |
|---|---|
| 等「学完了」再发 | 30 周后的总结没有过程吸引人。现在就开始，哪怕 W1 只有线代笔记 |
| 追求完美剪辑 | 技术内容的价值在信息密度，不在转场特效。手机录屏 + 讲清楚就够 |
| 同时铺 5 个平台 | 每平台都要适配格式，前期会累垮。先 B站 + 小红书跑通 8 周 |
| 内容和学习割裂 | 如果你发现为了做视频而没时间学习，说明流水线错了——回到「从产出长出来」 |
| 买粉刷 star | 虚假数据会毁掉信任，而且 GitHub 有刷 star 检测 |
| 泄露隐私 | 发布前检查：截图里有没有邮箱、token、向日葵设备码、文件路径里的个人信息 |

### 一个心理预期

前 8 周大概率增长缓慢——这是正常的冷启动。GitHub 和自媒体的复利都在后期：
当仓库有 30 个周的连续记录、60 条视频、一份完整的 Capstone，
它本身就是一个「活的作品集」，会带来工作机会、社区连接和后续内容的自然流量。

**先完成，再完美。** 周日把项目传上去，发第一条宣言，就开始计时了。
