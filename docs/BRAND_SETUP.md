# 三平台身份改造方案 · 从零建立统一品牌

> 写于 2026-11-23。基于你的实际情况：**GitHub 旧号不常用、B站几乎空白、小红书粉丝<100 笔记<20、
> 三个平台都选统一昵称和头像**。结论先给：**三个号都不换，一次性统一改造。**

---

## 一、决策结论与理由

| 平台 | 结论 | 理由 |
|---|---|---|
| **GitHub** | 用老号，可改名 | 免费号一人只能一个（ToS）；改名不影响 commit 归属，但**个人主页旧链接会 404**，所以一次想好 |
| **B站** | 用老号，直接改名 | 几乎空白 = 零历史负担；大会员对视频分发无加成，但改名冷却期较短，可利用 |
| **小红书** | **不换号，改造旧号** | 粉丝<100、笔记<20，换新号要重新养号且同设备多账号切换有风控风险；旧号改造成本更低 |

**为什么小红书不换号**：
- 换号要新手机号，且「单设备/IP 多账号切换」是平台明确的风控点
- 你旧号本来就没多少沉淀，标签混乱程度有限——用连续 15 条垂直内容就能覆盖
- 换号的"干净"优势，对于零基础账号几乎不存在

## 三、GitHub：先改名再推仓库（顺序很重要）

> ⚠️ **纠正一个常见误解**：改名后**仓库链接**会自动重定向，但 `github.com/旧用户名` **个人主页会 404**，
> gist 链接也会 404，@提及不会重定向。所以：**先改名，再上传项目，再对外分享链接**。

### 改名步骤

1. GitHub 右上角头像 → **Settings** → 左侧 **Account**（个人账户设置）
2. 找到 **Change username**，输入新用户名 → 确认
3. 立刻验证：`github.com/新用户名` 能打开，仓库链接能重定向

### 改名的 4 个副作用（提前处理）

| 影响 | 怎么处理 |
|---|---|
| 个人主页旧链接 404 | 改名后再生成对外链接，**别提前分享旧链接** |
| 本地 `git remote` 的 URL | 用 SSH 的话 `~/.ssh` 的 key 不用动，但要 `git remote set-url origin git@github.com:新用户名/仓库名.git` |
| 旧用户名被释放，别人可抢注 | 想好再改，改完别犹豫 |
| commit 邮箱 | 只要邮箱还绑在账号上，历史 commit 继续计入贡献图（本机 git 邮箱要在 Settings → Emails 验证过，见上传手册） |

**改完名再推仓库**，这样 README 里的 badge 链接、clone 地址、Pages 地址一次写对。
（项目里的链接已按 `jax-fox-lab/ai-selfstudy-30weeks` 写好，若主选被占用改用备选，需全局替换这个字符串。）

### 个人主页（同名仓库）

建一个和 GitHub 用户名**完全相同**的公开仓库，里面的 README 会显示在你的 GitHub 主页顶部。
内容保持 10 行以内：

```markdown
# 你的名字 · 软件工程 → AI

软件工程背景，2026.11–2027.06 用 30 周自学 AI，全程开源记录。

- 📚 [AI 硕士自学 30 周计划](https://github.com/jax-fox-lab/ai-selfstudy-30weeks) — 每周作业 + 打卡看板 + 真实产出
- 📝 当前进度：W01 / 30（自动更新见项目 README）
- 📫 联系：（邮箱或其他，可选）
```

## 四、B站：一次改到位

### 改造清单（按顺序，一次性做完）

1. **改昵称**：App → 我的 → 编辑资料 → 昵称。
   - 规则：2–10 个汉字或 4–20 字符；不能和已注册用户重复
   - 冷却期：各来源说法不一（大会员 30 天 / 普通 90 天 / 改名卡），**以你 App 内实际提示为准**
   - ⚠️ 改之前先在 B站搜索框搜一遍这个名字，确认没被占用，别浪费当月机会
2. **换头像**：上传 `docs/avatar.png`
3. **改签名**（网页端路径：右上角头像 → 个人中心 → 个人信息 → 编辑个人资料）。
   这是 B站唯一会在**主页、评论区、私信**里露出的文案位，空着是最大浪费。
   ⚠️ 签名上限说法不一（App 有说 70 字、网页端有说 100 字符），用下面这个 **65 字符稳妥版**，两边都塞得下：

```
软工背景 → 30周AI自学中，每周更新代码与踩坑
github.com/jax-fox-lab/ai-selfstudy-30weeks
```

   **放链接的安全边界**：B站规则禁止的是「诱导至第三方平台注册 / 关注 / 交易 / 领资源」，
   开源项目地址在签名里是技术区常规做法，风险很低。但**别写**「点击关注我」「进群领资料」
   这类话术，那才会被判违规推广。
   （完整版文案「软件工程背景 → AI 自学中｜2026.11–2027.06 共 30 周…」约 90 字符，
   若你的 App 实测支持 100 字可用；不确定就用上面的稳妥版。）

4. **背景图**：可用 `docs/social-preview.png` 裁切成横幅
5. **主页置顶**：等第一条视频发布后，置顶那条「开篇宣言」

### ⚠️ 先核对 UID 再填 GitHub 社交链接

B站**默认用户名**格式是 `bili_` + UID（例如 `bili_1234567890`）。如果 GitHub 个人资料里填的
`space.bilibili.com/<数字>` 跟它不一致，**那个链接很可能是错的**——挂错链接等于白引流。
核对方法（任选其一）：

- App → 我的 → 设置 → 账号资料 → 看 **UID** 那一栏
- 点进自己主页，地址栏 `space.bilibili.com/` 后面那串数字

B站接口有验证码，外部工具不一定能替你查；自己看一眼最稳。核对后把正确 UID 填进 GitHub 的 Social accounts 第 1 栏。

> 顺带：出生日期这类真实隐私字段，既然项目文档已做脱敏，账号侧也建议设成不公开或随便填一个——它对引流零价值。

**大会员的真实作用**：看高清、免广告、装扮——**对视频分发零加成**。别因为它而犹豫要不要换号思路；
但你既然有，改名冷却期可能更短，这是它在这里唯一有用的地方。

## 五、小红书：改造旧号，不要换

### 改造清单（严格按顺序，且一个月内只做这一次）

> ⚠️ **小红书的坑**：短期内频繁改昵称/头像/简介/背景图，会让账号标签持续错乱、触发风控观察期、大幅减少推流。
> 所以下面这些**一次性改完，然后至少 30 天不要再动**。

1. **先隐藏旧笔记**（不要删除）
   - 路径：笔记 → 右上角「…」→ 设为仅自己可见
   - 为什么隐藏不删除：批量删除会被系统认为「逃避内容审查」，反而增加风控概率
   - <20 条，半天能处理完
2. **一次性改完资料**：昵称 → 头像（`avatar.png`）→ 简介 → 背景图
3. **简介模板**（上限 100 字，这个 78 字可直接贴）：

```
软工背景｜30周自学AI，每周更新打卡·知识点·踩坑
代码和进度 → github.com/jax-fox-lab/ai-selfstudy-30weeks
```

> 别用旧版 115 字文案（「软件工程背景｜30 周自学 AI 中…」），**超出 100 字上限会被截断**。
> 小红书简介里的 `github.com/...` 是纯文本、不会变成可点链接，但用户能手动搜到——这是技术区常规做法。
> 别写「点击链接」「进群领资料」这类诱导话术，那才会触发风控。

4. **确认垂直标签**：改完后连续发 **15 条同主题内容**（都是 AI 自学相关），
   这是覆盖旧「日常」标签的关键——比改资料本身更重要
5. **发布节奏**：发布后 24 小时内不要修改笔记；发布后 1 小时内别反复刷数据

**如果旧号有违规记录**（被限流、被警告）：那就值得换新号了。判断方法——
发一条正常笔记，看小眼睛是否长期卡在 200 以下。但先别急着下结论，一条的数据波动很大。

## 附：常见误区

| 误区 | 真相 |
|---|---|
| 换号能「重新开始」拿到更多流量 | 新号没有历史数据，平台反而需要更长时间识别你；零粉丝旧号改造更划算 |
| 大会员能让 B站视频获得推荐 | 不能，那是消费权益 |
| 小红书改名能「刷新」账号标签 | 频繁改反而打乱标签；靠连续垂直内容才能重建 |
| GitHub 改名后所有旧链接都能用 | 只有仓库链接重定向，个人主页和 gist 会 404 |
| 三平台用不同头像更专业 | 统一头像才能建立跨平台认知，这是最低成本的品牌动作 |
